## 변수의 타입

> 크기가 플랫폼에 따라 달라지는 타입이 있어, 아래 설명은 **64비트(amd64)** 기준입니다.

### 정수형 타입
+ 크기가 고정된 타입
    - `int8` 8비트, -128 ~ 127
    - `int16` 16비트, -32,768 ~ 32,767
    - `int32` 32비트, -21억 ~ 21억
    - `int64` 64비트, -922경 ~ 922경
+ 부호 없는(unsigned) 타입도 있음
    - `uint8` 0 ~ 255
    - `uint16` 0 ~ 65,535
    - `uint32` 0 ~ 42억
    - `uint64` 0 ~ 1844경
    - 자바와 달리 부호 없는 정수형이 정식으로 존재함
+ 크기가 플랫폼에 따라 달라지는 타입
    - `int`, `uint` — 32비트 환경에서는 32비트, 64비트 환경에서는 64비트
    - `uintptr` — 포인터를 정수로 담을 수 있는 크기. `unsafe` 를 쓸 때가 아니면 볼 일 없음
+ **특별한 이유가 없으면 `int` 를 씀**
    - 크기를 명시해야 하는 경우에만 `int32`, `uint64` 등을 씀
    - 바이너리 포맷, 네트워크 프로토콜, 대량 데이터의 메모리 최적화 등
+ 오버플로우가 발생해도 예외가 나지 않음
    - 최댓값에 1을 더하면 최솟값으로 순환함
    - 다만 **상수 리터럴**로 범위를 넘기면 컴파일 에러임 (`var a int8 = 300`)

### 별칭 타입
+ `byte` = `uint8`
    - 바이트 데이터를 다룰 때 씀 (파일, 네트워크, `[]byte`)
+ `rune` = `int32`
    - 유니코드 코드 포인트 하나를 담음
+ 완전히 같은 타입이라 서로 바꿔 써도 컴파일됨
    - 그럼에도 구분해 쓰는 이유는 **의도를 드러내기 위함**임
    - `[]byte` 는 바이트 열, `[]rune` 은 문자 열이라는 뜻이 됨
+ 자바의 `char`(UTF-16 코드 유닛 16비트)와 달리 `rune` 은 32비트임
    - 이모지처럼 큰 코드 포인트도 `rune` 하나로 표현됨
    - 자바에서 서로게이트 페어 때문에 생기는 문제가 Go에는 없음

### 실수형 타입
+ `float32` 32비트, 정밀도 약 7자리
+ `float64` 64비트, 정밀도 약 15자리
+ **`float` 라는 타입은 없음**
    - 반드시 크기를 붙여야 함
    - 특별한 이유가 없으면 `float64` 를 씀
+ IEEE 754 방식이라 값이 정확하지 않음
    - `0.1 + 0.2` 의 결과가 `0.30000000000000004` 가 됨
    - 금액 계산에는 정수(최소 단위로 환산)나 `math/big`, `shopspring/decimal` 등을 씀

### 복소수형 타입
+ `complex64` — float32 실수부 + float32 허수부
+ `complex128` — float64 실수부 + float64 허수부
+ 언어 차원에서 복소수를 지원하는 것이 특이한 점임

    ```go
    c := 3 + 4i
    fmt.Println(real(c), imag(c))   // 3 4
    ```

+ 과학 계산이 아니면 쓸 일이 거의 없음

### 논리형 타입
+ `bool` — `true` 또는 `false`
+ **다른 언어와 달리 숫자나 문자열이 참·거짓으로 취급되지 않음**
    - `0`, `""`, `nil` 은 false가 아니라 그냥 값임
    - `if 1 { }` 은 컴파일 에러이며, 조건 자리에는 반드시 bool 표현식이 와야 함
    - `if len(s) != 0` 처럼 명시적으로 써야 함
+ 정수와 상호 변환되지 않음
    - `int(true)` 불가, `bool(1)` 불가

### 문자열 타입
+ `string` — **UTF-8 바이트 시퀀스이며 불변(immutable)** 임
    - `s[0] = 'a'` 는 컴파일 에러
    - 자바의 String과 마찬가지로 값이 바뀌지 않음
+ 인덱싱하면 문자가 아니라 **byte** 가 나옴
    - `s[0]` 의 타입은 `uint8`
+ `len()` 은 문자 수가 아니라 **바이트 수**를 돌려줌

    ```go
    s := "한글"
    fmt.Println(len(s))           // 6  (UTF-8에서 한글 한 글자는 3바이트)
    fmt.Println(len([]rune(s)))   // 2  (문자 수)
    ```

+ `range` 로 순회하면 **rune 단위**로 돌며, 인덱스는 바이트 위치임

    ```go
    for i, r := range "한글" {
        fmt.Println(i, string(r))   // 0 한 / 3 글
    }
    ```

    - 인덱스가 0, 1이 아니라 0, 3인 것에 주의
+ 문자열 연결은 새 문자열을 만들어냄
    - 반복문 안에서 `+=` 로 이어붙이면 매번 복사가 일어남
    - 반복이 많으면 `strings.Builder` 를 씀 (자바의 StringBuilder와 같은 역할)

### 제로값
+ Go는 **초기화하지 않은 변수를 자동으로 제로값으로 채움**
    - 쓰레기 값이 존재하지 않음
    - 자바에서 지역 변수를 초기화하지 않으면 컴파일 에러인 것과 다름
+ 타입별 제로값
    - 숫자 계열(int, float, complex) — `0`
    - `bool` — `false`
    - `string` — `""` (빈 문자열, `nil` 이 아님)
    - 포인터, 슬라이스, 맵, 채널, 함수, 인터페이스 — `nil`
    - 배열·구조체 — 각 요소·필드의 제로값으로 채워짐
+ 이 덕분에 `var buf bytes.Buffer` 처럼 **초기화 없이 바로 쓸 수 있는** 타입 설계가 가능해짐
    - "제로값이 쓸모 있게(zero value is useful)" 만드는 것이 Go의 설계 관례임
+ 다만 `nil` 이 제로값인 타입은 그대로 쓸 수 없는 경우가 있음
    - `nil` 맵에 쓰기는 런타임 패닉이므로 `make` 가 필요함
    - `nil` 슬라이스는 `append` 가 되므로 그대로 써도 됨

### 타입 추론
+ `:=` 나 `var x = ...` 로 선언하면 리터럴에서 타입이 정해짐
    - 정수 리터럴 `10` → `int`
    - 실수 리터럴 `3.14` → `float64`
    - 문자 리터럴 `'A'` → `rune` (= int32)
    - 문자열 리터럴 `"hi"` → `string`
    - `true` / `false` → `bool`
    - `3 + 4i` → `complex128`
+ **`f := 10` 은 float64가 아니라 int임**
    - 실수가 필요하면 `f := 10.0` 이나 `var f float64 = 10` 으로 써야 함
+ 타입 확인은 `%T` 로 함

    ```go
    fmt.Printf("%T\n", 3.14)   // float64
    ```

### 타입 변환
+ **Go에는 암묵적 타입 변환이 없음**
    - 자바의 자동 형변환(byte → int → long → double)에 해당하는 것이 없음
    - 범위가 넓어지는 방향이라도 직접 써줘야 함

    ```go
    var i int = 10
    var f float64 = float64(i)   // 필수. var f float64 = i 는 에러
    ```

+ 크기가 다르면 같은 정수끼리도 연산되지 않음

    ```go
    var a int32 = 1
    var b int64 = 2
    c := a + b          // 에러: mismatched types int32 and int64
    c := int64(a) + b   // OK
    ```

    - `int` 와 `int64` 도 크기가 같아도 **다른 타입**이라 변환이 필요함
+ 변수를 변환할 때는 값이 조용히 바뀔 수 있음
    - 실수 → 정수는 반올림이 아니라 **소수점 절삭**임 (`3.9` → `3`, `-3.9` → `-3`)
    - 범위를 벗어나면 비트가 잘려나감 (`int32` 변수 `300` → `int8` 은 `44`)
    - 둘 다 에러가 나지 않으므로 직접 확인해야 함
+ **상수는 반대로, 손실이 생기는 변환을 아예 막음**
    - 값이 정확히 표현될 때만 허용되므로 컴파일 타임에 걸러짐

    ```go
    int(3.9)        // 에러: cannot convert 3.9 (untyped float constant) to type int
    var x int8 = 300 // 에러: cannot use 300 as int8 value (overflows)

    var f float64 = 3.9
    int(f)          // OK. 3
    ```

    - 상수는 컴파일러가 값을 알고 있으니 실수를 잡아주고, 변수는 런타임 값이라 그냥 통과시키는 것
+ 숫자 ↔ 문자열은 변환이 아니라 `strconv` 패키지를 씀
    - `string(65)` 는 `"65"` 가 아니라 **`"A"`** 임 (코드 포인트로 해석)
    - 의도한 경우가 드물어 `go vet` 이 경고함

    ```go
    strconv.Itoa(65)                // "65"
    n, err := strconv.Atoi("65")    // 문자열 → int
    strconv.FormatFloat(3.14, 'f', 2, 64)   // "3.14"
    ```

### 상수
+ `const` 로 선언하며 컴파일 타임에 값이 정해짐
    - **미사용이어도 에러가 나지 않음**
    - 함수 안팎 어디서나 선언할 수 있음
+ `iota` 로 연속된 값을 만듦

    ```go
    const (
        A = iota   // 0
        B          // 1
        C          // 2
    )
    ```

    - 자바의 enum 자리를 대신하는 관용구임
+ 타입을 붙이지 않으면 **무타입 상수(untyped constant)** 가 됨
    - 쓰이는 자리에 맞춰 타입이 정해지므로 변환 없이 여러 타입에 대입됨

    ```go
    const n = 10
    var f float64 = n   // OK
    var i int = n       // OK

    const m int = 10
    var f2 float64 = m  // 에러. float64(m) 필요
    ```

    - 암묵적 변환이 없는 언어에서 숫자 리터럴을 편하게 쓰게 해주는 장치임
+ 상수가 될 수 있는 것은 기본 타입뿐임
    - 슬라이스, 맵, 구조체는 상수가 될 수 없음

### 복합 타입
+ 기본 타입을 조합해 만드는 타입들이며, 각각 별도로 정리할 주제임
    - 배열 `var a [5]int` — **길이가 타입의 일부**임. `[3]int` 와 `[5]int` 는 다른 타입
    - 슬라이스 `var s []int` — 가변 길이. 실무에서는 배열보다 압도적으로 많이 씀
    - 맵 `var m map[string]int` — 키-값 쌍
    - 구조체 `type P struct { Name string }` — 필드 묶음. 자바의 클래스 자리
    - 포인터 `var p *int` — 주소값. 포인터 연산은 불가능함
    - 함수 `var f func(int) int` — 함수도 값이며 변수에 담을 수 있음
    - 인터페이스 `var r io.Reader` — 메서드 집합
    - 채널 `var ch chan int` — 고루틴 간 통신
+ 슬라이스·맵·채널은 제로값이 `nil` 이라 `make` 로 초기화해야 함

    ```go
    s := make([]int, 0, 10)      // 길이 0, 용량 10
    m := make(map[string]int)
    ```

### 사용자 정의 타입
+ `type 새이름 기존타입` — **새로운 타입**을 만듦
    - 기존 타입과 별개라서 서로 대입되지 않음

    ```go
    type Celsius float64

    var c Celsius = 36.5
    var f float64 = c            // 에러
    var f float64 = float64(c)   // OK
    ```

    - 섭씨와 화씨를 섞어 쓰는 실수를 컴파일 타임에 막을 수 있음
+ `type 새이름 = 기존타입` — **별칭**이며 완전히 같은 타입임
    - `type MyInt = int` 이면 `MyInt` 와 `int` 는 구분되지 않음
    - `byte`, `rune` 이 이 방식으로 정의되어 있음
    - 주로 패키지를 옮길 때 하위 호환을 위해 씀
+ `=` 하나 차이로 의미가 완전히 달라지므로 주의해야 함

### 정리
+ 자주 쓰는 것만 추리면
    - 정수는 `int`, 실수는 `float64`, 나머지는 `string` `bool`
+ 자바와 다른 점
    - 부호 없는 정수형이 있음
    - 지역 변수도 제로값으로 자동 초기화됨
    - 암묵적 형변환이 전혀 없음 (`int32 + int64` 도 에러)
    - `0`, `""`, `nil` 이 false로 취급되지 않음
    - 문자는 UTF-16이 아니라 UTF-8 기준이며 `rune` 은 32비트
+ 함정
    - `f := 10` 은 int임
    - `len("한글")` 은 2가 아니라 6임
    - `int(3.9)` 는 컴파일 에러임. 변수를 변환하면 절삭되어 3
    - `string(65)` 는 `"65"` 가 아니라 `"A"` 임
+ `type A B` 는 새 타입, `type A = B` 는 별칭임
