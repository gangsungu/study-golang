## 변수 선언과 사용

### 변수를 선언하는 방법
+ `var 이름 타입 = 값` — 가장 온전한 형태
    - `var a int = 10`
+ 타입 생략 — 값에서 타입을 추론함
    - `var a = 10`
+ 값 생략 — 제로값으로 초기화됨 (타입은 필수)
    - `var a int` → `0`
+ 짧은 선언 `:=` — **함수 안에서만** 사용 가능
    - `a := 10`
    - 패키지 레벨(함수 밖)에서는 쓸 수 없고 `var` 를 써야 함
    - 실무에서 함수 내부는 대부분 `:=` 를 씀
+ 여러 개를 한 번에 선언
    - `var x, y int = 1, 2`
    - `a, b := 1, "hello"` — 타입이 서로 달라도 됨
+ 블록으로 묶기
    - 패키지 레벨 변수를 모아둘 때 주로 씀

    ```go
    var (
        name string = "gopher"
        age  int    = 10
        ok   bool
    )
    ```

### := 의 재선언 규칙
+ 왼쪽에 **새 변수가 최소 하나** 있어야 함
    - 이미 선언된 변수만 나열하면 `no new variables on left side of :=`
+ 새 변수가 하나라도 있으면 나머지는 재선언이 아니라 **대입**으로 처리됨

    ```go
    a, err := f()
    b, err := g()   // OK. b가 새 변수라서 err는 그냥 대입됨
    a, b := h()     // 에러. 둘 다 이미 선언되어 있음
    ```

    - `err` 를 매번 새로 만들지 않아도 되도록 만든 편의 규칙
+ 스코프가 다르면 이야기가 달라짐
    - 안쪽 블록에서 `:=` 를 쓰면 **바깥 변수를 가리는 새 변수**가 만들어짐 (섀도잉)

    ```go
    err := f()
    if cond {
        err := g()   // 바깥 err가 아니라 새로운 err
        _ = err
    }
    // 바깥 err는 g()의 결과를 못 받음 — 흔한 버그
    ```

    - `go vet -vettool=shadow` 나 린터로 잡을 수 있음

### 지역 변수는 반드시 사용해야 함
+ 함수 안에서 선언한 변수를 쓰지 않으면 **컴파일 에러**임
    - 린터 경고가 아니라 빌드 자체가 실패함

    ```go
    func main() {
        var a int = 10
        var msg string = "Hello, Variable!"
    }
    ```

    ```
    declared and not used: a
    declared and not used: msg
    ```

+ Error Lens 같은 확장은 이 에러를 에디터에 미리 보여주는 것일 뿐임
    - 확장을 꺼도 컴파일 시점에 똑같이 막힘
+ **대입만 하는 것은 사용으로 치지 않음**
    - 값을 읽어야 사용으로 인정됨

    ```go
    a := 10
    a = 20      // 여전히 declared and not used
    ```

+ import에도 같은 규칙이 적용됨
    - `imported and not used: "os"`

### 미사용이 허용되는 것
+ 패키지 레벨 변수 (함수 밖의 `var`)
    - 다른 파일이나 패키지에서 참조할 수 있으므로 컴파일러가 판단할 수 없음
+ 함수 매개변수
    - 인터페이스를 만족시키기 위해 시그니처를 맞춰야 하는 경우가 있음
+ 이름 붙인 반환값
+ 상수 `const`
    - 컴파일 타임에 값으로 치환되어 사라짐
+ 구조체 필드
+ 반대로 **허용되지 않는 것은 두 가지뿐임**
    - 함수 내 지역 변수, 그리고 import

### 빈 식별자 `_`
+ 값을 버리겠다고 명시하는 특수한 이름임
    - `_` 에 대입된 값은 사용 검사 대상이 아님
    - 읽을 수도 없음 (`fmt.Println(_)` 은 에러)
+ 쓰이는 곳

    ```go
    _ = a                    // 선언은 유지하되 에러만 없애기 (디버깅 중 임시)
    _, err := f()            // 첫 번째 반환값이 필요 없을 때
    for _, v := range list   // 인덱스가 필요 없을 때
    import _ "github.com/lib/pq"   // init()만 실행하고 이름은 안 씀
    var _ io.Reader = (*MyType)(nil)  // 컴파일 타임 인터페이스 구현 검사
    ```

+ `_ = a` 는 임시방편임
    - 커밋 전에는 변수를 실제로 쓰거나 지우는 게 맞음

### 왜 이런 규칙이 있나
+ 안 쓰는 변수는 대부분 **실수의 흔적**임
    - 오타, 리팩터링 중 남은 찌꺼기
    - 쓰려던 변수 대신 다른 변수를 쓴 진짜 버그
+ **경고로 두면 아무도 안 본다**는 것이 Go 팀의 판단이었음
    - 경고는 쌓이면 무시되므로 아예 에러로 강제함
+ 컴파일 속도에도 이득이 있음
    - 죽은 코드를 애초에 못 만들게 하므로 컴파일러가 할 일이 줄어듦
+ "선택의 여지를 없애서 논쟁을 없앤다"는 Go의 전반적인 방침과 같은 맥락임
    - `gofmt` 하나로 포맷을 통일한 것과 같은 이유

### 정리
+ 컴파일 에러가 되는 것
    - 사용하지 않은 **지역 변수**, 사용하지 않은 **import**
+ 허용되는 것
    - 패키지 레벨 변수, 매개변수, 반환값 이름, 상수, 구조체 필드
+ 사용의 기준
    - **읽어야** 사용임. 대입만으로는 부족함
+ 빠져나가는 법
    - `_` 로 명시적으로 버리기
+ 선언 방법
    - 함수 밖은 `var`, 함수 안은 주로 `:=`
