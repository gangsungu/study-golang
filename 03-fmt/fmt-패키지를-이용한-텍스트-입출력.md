## fmt 패키지를 이용한 텍스트 입출력

### fmt 패키지
+ Go에서 **표준 입출력**을 담당하는 패키지임
    - 표준 출력(화면)에 쓰는 함수와 표준 입력(키보드)에서 읽는 함수를 함께 제공함
    - 이름은 format의 줄임말임
+ 자바와 대응시키면
    - 출력은 `System.out.print` / `println` / `printf`
    - 입력은 `Scanner` 의 `nextInt()` 등
    - 자바는 출력(`System.out`)과 입력(`Scanner`)이 따로지만, Go는 **한 패키지에 대칭으로** 들어 있음

### 출력 함수 세 가지
+ `Print()` — 입력값들을 그대로 출력함
+ `Println()` — 입력값들을 출력하고 **개행**함
+ `Printf()` — **서식**에 맞춰 입력값들을 출력함
    - 개행을 하지 않으므로 서식 끝에 `\n` 을 직접 넣어야 함
+ `Print` 와 `Println` 은 **공백을 넣는 규칙이 다름**

    ```go
    fmt.Print("a", "b", 1, 2, "c", 3.5, true)    // ab1 2c3.5 true
    fmt.Println("a", "b", 1, 2, "c", 3.5, true)  // a b 1 2 c 3.5 true
    ```

    - `Println` 은 피연산자 사이에 **항상** 공백을 넣음
    - `Print` 는 **양쪽 모두 문자열이 아닐 때만** 공백을 넣음. 그래서 `"a","b"` 는 붙고 `1,2` 는 띄워짐
    - 자바의 `print` 는 인자를 하나만 받으므로 이런 규칙 자체가 없음
+ 세 함수 모두 `(쓴 바이트 수, 에러)` 를 반환함
    - `n, err := fmt.Println("한글")` → `7 <nil>` (한글 6바이트 + 개행 1바이트)
    - 화면 출력에서 에러가 날 일은 거의 없으므로 **보통은 반환값을 무시함**
    - 자바의 `println` 은 `void` 임. Go는 에러를 반환값으로 돌려주는 것이 기본 관례라서 출력 함수도 예외가 아님
+ 접두사만 바꾸면 **출력 대상**이 달라짐

    | 접두사 | 출력 대상 | 예 | 자바 |
    |:------:|----------|-----|------|
    | 없음 | 표준 출력 | `fmt.Printf` | `System.out.printf` |
    | `S` | 문자열로 **반환** | `fmt.Sprintf` | `String.format` |
    | `F` | 지정한 곳 (`io.Writer`) | `fmt.Fprintf(os.Stderr, ...)` | `System.err.printf`, `PrintWriter` |

    - `Sprint`, `Sprintln`, `Fprint`, `Fprintln` 도 똑같이 있음
    - 이 규칙은 입력 함수에도 그대로 적용됨 (`Sscan`, `Fscan`)

### 서식 문자 (verb)
+ `Printf` 의 서식 안에서 `%` 로 시작하는 자리 표시자임
+ 무엇이든 출력하는 `%v` 계열

    | 서식 | 출력 | `point{1, "y"}` 의 결과 |
    |:----:|------|------------------------|
    | `%v` | 기본 형식 | `{1 y}` |
    | `%+v` | 구조체 필드 이름 포함 | `{X:1 Y:y}` |
    | `%#v` | Go 문법 그대로 | `main.point{X:1, Y:"y"}` |
    | `%T` | 타입 | `main.point` |

    - **타입을 모르겠으면 `%v`** 를 쓰면 됨. `Println` 이 쓰는 형식이 이것임
    - 디버깅할 때는 `%+v` 가 가장 유용함
    - 자바에서 객체를 출력하면 `toString()` 을 오버라이드하지 않는 한 `Point@1b6d3586` 이 나오지만, Go는 **필드 값을 알아서 펼쳐 줌**
+ 타입별 서식

    | 서식 | 대상 | 설명 |
    |:----:|------|------|
    | `%d` | 정수 | 10진수 |
    | `%b` `%o` `%x` `%X` | 정수 | 2진수, 8진수, 16진수(소문자/대문자) |
    | `%c` | 정수(rune) | 문자 하나 |
    | `%U` | 정수(rune) | 유니코드 코드포인트 (`U+D55C`) |
    | `%f` | 실수 | 소수점 표기 (기본 6자리) |
    | `%e` | 실수 | 지수 표기 (`1.234568e+03`) |
    | `%g` | 실수 | `%e` 와 `%f` 중 간결한 쪽 |
    | `%s` | 문자열 | 그대로 |
    | `%q` | 문자열 | 따옴표로 감싸고 특수문자를 이스케이프 (`"go"`) |
    | `%t` | bool | `true` / `false` |
    | `%p` | 포인터 | 주소 |
    | `%%` | — | `%` 문자 자체 |

    - `%q` 는 빈 문자열이나 공백·개행이 섞인 문자열을 확인할 때 좋음 (`""` 처럼 눈에 보임)
+ 서식과 인자가 맞지 않아도 **패닉도 컴파일 에러도 나지 않음**
    - 대신 출력 안에 표시가 남음

    ```
    %!d(string=x)       # 타입 불일치: %d 자리에 문자열
    %!d(MISSING)        # 인자 부족
    %!(EXTRA int=2)     # 인자 초과
    ```

    - 자바는 실행 중에 **예외**가 남 (`IllegalFormatConversionException`, `MissingFormatArgumentException`). 반면 인자 초과는 조용히 무시함
+ 이런 실수는 **`go vet` 이 실행 전에 잡아 줌**
    - `fmt.Printf format %d has arg name of wrong type string`
    - `Println` 에 `%d` 를 넣은 실수도 잡음 (`Println` 은 서식을 해석하지 않으므로 `%d` 가 그대로 출력됨)
    - 컴파일러가 아니라 `vet` 의 몫이라 `go build` 는 통과함. 그래서 `go vet` 을 습관처럼 돌려야 함

### 너비, 플래그, 정밀도
+ 서식 문자 앞에 붙여서 모양을 맞춤
    - 형태: `%[플래그][너비][.정밀도]서식` (`%08.2f` = 플래그 `0`, 너비 `8`, 정밀도 `2`)
+ **너비**는 최소 너비임
    - 값이 짧으면 빈칸을 채우고, **기본은 오른쪽 정렬**임
    - 값이 너비보다 길면 **자르지 않고** 그대로 출력함 (`%5d` 에 `123456789` → `123456789`)
+ 플래그

    | 서식 | `123` 의 결과 | 의미 |
    |:----:|:------------:|------|
    | `%5d` | `[  123]` | 오른쪽 정렬, 빈칸은 공백 |
    | `%05d` | `[00123]` | 오른쪽 정렬, 빈칸은 **0** |
    | `%-5d` | `[123  ]` | **왼쪽** 정렬, 빈칸은 공백 |
    | `%-05d` | `[123  ]` | `0` 이 **무시됨** |
    | `%+d` | `[+123]` | 양수에도 부호 |

    - `0` 은 정렬을 바꾸는 플래그가 아님. 오른쪽 정렬은 그대로이고 **채우는 문자만** 0으로 바꿈
    - `-` 와 `0` 을 같이 쓰면 `0` 이 무시됨. 오른쪽에 0을 채우면 `12300` 처럼 **값이 달라 보이기** 때문임
+ **정밀도**는 서식에 따라 뜻이 다름
    - `%f` — 소수점 **이하 자릿수** (`%.2f` 에 `324.13455` → `324.13`)
    - `%g` — **유효숫자 개수** (`%.5g` → `324.13`, `%.2g` → `3.2e+02`)
        - 유효숫자 2개로는 `324` 를 표현할 수 없어서 지수 표기로 바뀜
    - `%s` — **최대 글자 수** (`%.2s` 에 `"golang"` → `go`)
+ 너비에는 소수점과 소수부도 포함됨
    - `%8.2f` → `[  324.13]` 처럼 전체가 8칸
+ 반올림은 **짝수 쪽으로** 함 (round half to even)
    - `%.0f` 에 `2.5` → `2`, `3.5` → `4`
    - 자바의 `String.format("%.0f", 2.5)` 는 `3` 임 (`HALF_UP`). 같은 서식인데 결과가 다름
+ 문자열의 너비는 바이트가 아니라 **rune(글자) 수** 기준임
    - `%5s` 에 `"한글"` → 공백 3칸 + 2글자
    - 하지만 한글은 화면에서 2칸을 차지하므로 **눈으로 보면 정렬이 어긋남**. 한글 표를 맞출 때 주의
+ 너비를 `*` 로 두면 인자로 받을 수 있음 (`%*d` 에 `7, 123` → `[    123]`)

### 입력 함수 세 가지
+ `Scan()` — 공백으로 구분된 값을 읽음. **개행도 공백으로 취급**함
+ `Scanln()` — 한 줄을 읽음. **개행에서 멈춤**
+ `Scanf()` — **서식**에 맞춰 값을 읽음
+ 값을 반환하는 게 아니라 **변수의 주소를 받아서 채워 넣음**

    ```go
    var a, b int
    n, err := fmt.Scanln(&a, &b)   // & 로 주소를 넘긴다
    ```

    - 자바의 `int a = sc.nextInt();` 처럼 값을 돌려받는 방식이 아님
    - 반환값은 `(읽은 개수, 에러)` 임
    - 실패해도 **예외가 아니라 에러 값**이 돌아옴. 자바처럼 `InputMismatchException` 을 `try-catch` 하지 않고 `if err != nil` 로 확인함
+ `&` 를 빼먹어도 **컴파일은 통과함**
    - 인자 타입이 `...any` 라서 아무 값이나 받기 때문임
    - 실행해 보면 `type not a pointer: int` 에러가 돌아옴
+ 함수별 차이 (입력이 `"1\n2"` 일 때)

    | 함수 | 결과 | 이유 |
    |------|------|------|
    | `Scan(&a, &b)` | `2 <nil>` → `1 2` | 개행을 건너뛰고 다음 줄까지 읽음 |
    | `Scanln(&a, &b)` | `1 unexpected newline` → `1 0` | 첫 줄에서 멈춤 |

    - `Scanln` 은 값이 **남아도** 에러임 (`"1 2 3"` → `expected newline`)
    - `Scanf` 는 서식 문자열과 **정확히** 일치해야 함 (`"%d,%d"` 에 `"1 2"` → `input does not match format`)
+ 문자열 변수로 읽으면 **공백에서 끊김**
    - `"hello world"` 를 `Scan(&s)` 하면 `hello` 만 들어감
    - 자바의 `next()` 와 같음. 한 줄 전체(`nextLine()`)가 필요하면 `bufio` 를 써야 함 (아래)
+ 실패해도 **앞에서 읽은 값은 이미 저장되어 있음**
    - `"3 x"` → `a` 에는 3이 들어가고 `1 expected integer`

### Scan 함수의 동작 원리
+ 사용자가 입력하면 데이터는 **표준 입력 스트림**이라는 메모리 공간에 임시 저장됨
    - `Scan` 계열 함수는 여기에 쌓인 데이터를 읽어서 처리함
    - 먼저 입력된 데이터부터 읽으므로 **FIFO** 구조임
    - 연속된 데이터 흐름이라서 **한 번 읽은 데이터는 다시 읽을 수 없음**
+ 스트림을 앞에서부터 하나씩 읽으며 **원하는 타입인지 확인**함
    - 원하는 타입이 아니면 그 자리에서 멈추고 에러를 반환함
    - 이때 **읽지 못한 나머지는 스트림에 그대로 남음**
+ 남은 데이터는 **다음 입력 함수가 읽어 버림**
    - `Scanln(&a, &b)` 를 반복하면서 `3 a b` 를 입력하면

    ```
    1번째: 3은 읽고 a에서 실패      → a는 소비되고 " b\n" 이 남음
    2번째: 남은 b를 읽다가 실패     → 사용자는 입력한 적도 없는데 에러
    3번째: 남은 개행만 읽고 실패    → unexpected newline
    4번째: 그제야 다음 줄 "5 6" 을 읽음
    ```

    - 그래서 **에러가 나면 남은 입력을 버리는 처리**가 필요함
    - 자바에서 `nextInt()` 뒤의 `nextLine()` 이 남은 개행을 읽어 빈 문자열이 되는 문제와 같은 원인임

### 입력 버퍼 비우기
+ 강의에서 쓴 방법 — 에러가 나면 개행까지 읽어서 버림

    ```go
    stdin := bufio.NewReader(os.Stdin)

    n, err := fmt.Scanln(&a, &b)
    if err != nil {
        stdin.ReadString('\n')   // 개행까지 읽어서 버린다
    }
    ```

    - 키보드로 입력할 때는 잘 동작함
+ 하지만 **`bufio.Reader` 는 한 번에 넉넉히(기본 4096바이트) 읽어 둠**
    - 키보드 입력은 운영체제가 한 줄씩 넘겨주므로 문제가 드러나지 않음
    - 파이프나 파일로 여러 줄을 한꺼번에 넣으면 `ReadString` 이 **다음 줄들까지 버퍼로 가져가 버림**. 이후 `fmt.Scanln` 은 읽을 게 없어 `EOF` 를 받음

    ```bash
    $ printf '3 a\n5 6\n' | go run .
    1 expected integer
    0 EOF               # "5 6" 은 bufio 버퍼 안에 갇혀 있다
    ```

    - `fmt.Scanln`(버퍼 없이 `os.Stdin` 을 직접 읽음)과 `bufio.Reader` 가 **같은 스트림을 따로 읽고 있는 것**이 원인임
+ 그래서 실무에서는 **한 줄을 통째로 읽은 뒤 파싱**하는 방식을 씀

    ```go
    sc := bufio.NewScanner(os.Stdin)
    for sc.Scan() {                       // 한 줄 읽기 (개행은 제거됨)
        line := sc.Text()
        var a, b int
        if _, err := fmt.Sscanln(line, &a, &b); err != nil {
            fmt.Println("잘못된 입력:", line)   // 이 줄만 버려진다
            continue
        }
        fmt.Println(a, b)
    }
    ```

    - 입력은 `bufio.Scanner` 하나만 읽으므로 버퍼가 엇갈리지 않음
    - 실패해도 **그 줄만 버려지므로** 버퍼를 비울 필요 자체가 없음
    - 자바에서 `nextLine()` 으로 읽고 `Integer.parseInt()` 로 바꾸는 방식과 같은 발상임
    - 줄 단위로 읽고 나면 `fmt.Sscan` 대신 `strings.Fields` + `strconv.Atoi` 로 파싱하기도 함
+ `\r\n`(Windows 개행)은 `Scanln` 과 `bufio.Scanner` 모두 알아서 처리함

### 정리
+ 출력
    - `Print` 그대로, `Println` 공백+개행, `Printf` 서식
    - 접두사 `S` 는 문자열 반환, `F` 는 지정한 곳으로 출력
    - 모르겠으면 `%v`, 디버깅은 `%+v`, 타입 확인은 `%T`
+ 서식
    - `%[플래그][너비][.정밀도]서식`
    - `0` 은 채우는 문자, `-` 는 왼쪽 정렬. 둘을 같이 쓰면 `0` 이 무시됨
    - 정밀도는 `%f` 에서 소수점 이하 자릿수, `%g` 에서 유효숫자, `%s` 에서 최대 글자 수
+ 입력
    - 주소(`&`)를 넘겨서 채워 받음. 반환값은 `(읽은 개수, 에러)`
    - `Scan` 은 개행을 넘어가고, `Scanln` 은 개행에서 멈추고, `Scanf` 는 서식과 정확히 맞아야 함
    - 실패한 입력은 스트림에 남아 다음 입력을 망가뜨림 → **줄 단위로 읽고 파싱**하는 게 안전함
+ 자바와 다른 점
    - 출력 함수도 `(바이트 수, 에러)` 를 반환함
    - 구조체는 `toString()` 없이도 필드가 출력됨
    - 서식 불일치가 예외가 아니라 출력 속 `%!d(...)` 표시로 나타나고, `go vet` 이 미리 잡음
    - `%.0f` 반올림이 짝수 쪽 (`2.5` → `2`)
    - 입력은 값을 반환받지 않고 주소를 넘겨 채움. 실패도 예외가 아니라 에러 값
+ 함정
    - `Printf` 는 개행을 안 함
    - `Println("%d", x)` 는 서식을 해석하지 않음
    - `Scan(a)` 처럼 `&` 를 빼도 컴파일은 됨
    - `fmt.Scan` 과 `bufio.Reader` 를 섞어 쓰면 버퍼가 엇갈림
