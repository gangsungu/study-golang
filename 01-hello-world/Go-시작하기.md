## Go 시작하기

### 모든 Go 파일은 패키지 선언으로 시작함
+ 파일 첫 줄은 반드시 `package 이름` 이어야 함
    - 주석은 그 위에 올 수 있지만, 코드로서는 패키지 선언이 가장 먼저임
    - 패키지 = 코드를 묶는 단위이며, **폴더 하나가 패키지 하나**임
+ 같은 폴더 안의 모든 `.go` 파일은 패키지 이름이 같아야 함
    - 한 폴더에 `package main` 과 `package util` 을 섞으면 컴파일 에러
+ 패키지 이름은 관례상 소문자 한 단어를 씀
    - 언더스코어나 카멜케이스를 쓰지 않음 (`httputil` O, `http_util` X)

### main 패키지와 main 함수
+ 실행 가능한 프로그램이 되려면 **두 조건을 모두** 만족해야 함
    - 패키지 이름이 `main`
    - 그 안에 매개변수도 반환값도 없는 `func main()` 이 존재
+ 둘 중 하나라도 빠지면 실행 파일이 만들어지지 않음
    - `package util` 에 `func main()` 을 써도 에러는 안 나지만, 그냥 이름이 main인 평범한 함수일 뿐임
    - 실행하려 하면 `package demo/util is not a main package`
+ `main()` 은 프로그램 진입점이며 인자를 받지 않음
    - C나 Java와 달리 매개변수로 명령행 인자를 받지 않음
    - 명령행 인자는 `os.Args` 로 읽음

### 진입점은 클래스가 아니라 폴더에 붙음 (자바와의 차이)
+ 진입점을 **무엇으로 지정하는가**가 다름
    - 자바는 **클래스**에 붙음. 어떤 클래스든 `main` 을 가질 수 있고, 실행할 때 클래스를 고름 (`java Foo`)
    - Go는 **패키지(폴더)** 에 붙음. `package main` 안에서만 진입점이 되고, 실행할 때 폴더를 지정함 (`go run ./app1`)
    - 자바에 있는 "실행할 클래스 골라잡기"가 Go에는 없음. **폴더가 곧 실행 단위**임
+ 한 폴더에는 `func main()` 이 **딱 하나**만 있을 수 있음
    - 파일을 나눠도 같은 패키지면 같은 이름공간이라 중복 선언이 됨

    ```
    same\b.go:3:6: main redeclared in this block
        same\a.go:3:6: other declaration of main
    ```

    - 파일마다 클래스가 따로라 각자 `main` 을 가질 수 있는 자바와 반대임
+ 반면 **폴더가 다르면 `package main` 이 몇 개든 상관없음**
    - 실행 파일이 그만큼 만들어질 뿐임
    - 이 레포의 예제가 그 구조임. 예제 폴더 하나가 곧 실행 파일 하나라서 서로 충돌하지 않음
    - 실무에서도 서버·배치·CLI를 한 레포에 담을 때 `cmd/server/`, `cmd/worker/` 처럼 폴더로 나눔
+ 그래서 "패키지마다 main이 있다"가 아니라 **"실행 파일 하나당 main 하나"** 로 이해해야 함

### init 함수
+ 패키지가 처음 로드될 때 **자동으로** 실행되는 함수임
    - 매개변수도 반환값도 없음
    - 직접 호출할 수 없음
    - 자바의 static 초기화 블록에 해당함
+ **패키지 단위로 존재하는 것은 `main` 이 아니라 이쪽임**
    - 패키지마다 가질 수 있고, 한 패키지에 여러 개를 둬도 됨 (파일마다 하나씩도 가능)
    - `main` 은 프로그램 전체에 하나, `init` 은 패키지 단위로 여럿
+ 실행 순서는 **import한 패키지부터 안쪽에서 바깥쪽으로** 진행됨
    - 각 패키지 안에서는 `패키지 변수 초기화` → `init()` 순서임

    ```
    1. (프로그램 시작)
    2. sub 패키지 변수 초기화
    3. sub의 init()
    4. main 패키지 변수 초기화
    5. main.go의 init()
    6. trace.go의 init()    ← 한 패키지에 init 여러 개 가능
    7. main()
    ```

    - 의존하는 패키지의 초기화가 항상 먼저 끝나 있음이 보장됨
    - 같은 패키지 안 여러 `init` 의 순서는 파일 이름 순이지만, **여기에 의존하는 코드를 쓰면 안 됨**
+ 남용하면 실행 순서를 따라가기 어려워지므로 꼭 필요할 때만 씀
    - 드라이버 등록이 대표적인 정당한 용례임 (`import _ "github.com/lib/pq"`)
    - 단순한 값 준비는 `init` 대신 그냥 패키지 변수 초기화로 하는 편이 읽기 쉬움

### import
+ 다른 패키지를 가져다 쓸 때 사용함
    - `fmt` 는 표준 입출력을 담당하는 내장 패키지
    - `Println`, `Printf` 처럼 **대문자로 시작하는 이름만** 외부에서 접근 가능함 (Go의 접근 제어 방식)
+ 여러 개를 가져올 때는 괄호로 묶음

    ```go
    import (
        "fmt"
        "os"
        "strings"
    )
    ```

+ **사용하지 않는 import는 컴파일 에러임**
    - `imported and not used: "os"`
    - 변수와 같은 규칙이며, 자세한 내용은 [변수 선언과 사용](../02-variables/변수-선언과-사용.md) 참고
+ 부수 효과(init 함수 실행)만 필요하면 `_` 를 붙여 이름 없이 가져옴

    ```go
    import _ "github.com/lib/pq"
    ```

### 세미콜론과 중괄호
+ 문장 끝에 세미콜론을 쓰지 않음
    - 실제로는 컴파일러가 줄 끝에 자동으로 넣어줌 (세미콜론 자동 삽입)
+ 그래서 **여는 중괄호를 다음 줄에 쓸 수 없음**

    ```go
    func main()
    {           // 에러: func main() 뒤에 세미콜론이 자동 삽입되어 버림
    }
    ```

    - K&R 스타일(같은 줄에 `{`)이 문법적으로 강제되는 셈임
+ 포맷은 `gofmt` 가 강제함
    - 들여쓰기는 스페이스가 아니라 **탭**
    - 취향 논쟁이 없도록 표준 포맷터 하나로 통일한 것이 Go의 방침
    - 대부분의 에디터가 저장 시 자동 실행되도록 설정되어 있음

### 실행 방법
+ `go run` — 컴파일 후 바로 실행하고 실행 파일은 남기지 않음
    - 학습·확인용

    ```bash
    go run ./01-hello-world/examples/ex01-hello
    go run main.go              # 파일을 직접 지정해도 됨
    ```

+ `go build` — 실행 파일을 만듦
    - 결과물 이름은 기본적으로 **폴더 이름**을 따라감 (`tutorial/` 에서 빌드하면 `tutorial.exe`)
    - `-o` 로 이름을 지정할 수 있음

    ```bash
    go build -o hello.exe ./01-hello-world/examples/ex01-hello
    ```

+ `go vet` — 컴파일은 되지만 의심스러운 코드를 잡아줌
+ `go fmt` — 소스를 표준 포맷으로 정렬함

### go.mod
+ 모듈(프로젝트) 단위를 정의하는 파일이며, 레포 루트에 하나 둠

    ```
    module hello

    go 1.27.1
    ```

+ `module` 은 이 프로젝트의 이름이자 import 경로의 접두사임
    - `hello/02-variables/examples/ex01-declaration` 같은 형태로 조합됨
+ **import 경로에는 한글을 쓸 수 없음**
    - `malformed import path: invalid char '변'`
    - 그래서 이 레포는 `.go` 파일이 들어가는 폴더 이름을 영문으로 둠
+ `go mod init 모듈이름` 으로 생성함

### 정리
+ 파일 구조
    - 패키지 선언 → import → 코드 순서
+ 실행되려면
    - `package main` + `func main()` 둘 다 필요
+ 진입점의 단위 (자바와 가장 다른 지점)
    - 자바는 클래스에, Go는 **폴더**에 붙음
    - 한 폴더에 `main` 은 하나. 폴더가 다르면 `main` 패키지가 여러 개여도 됨
    - "패키지마다 main"이 아니라 **"실행 파일 하나당 main 하나"**
+ 패키지 단위로 여럿인 것은 `init`
    - import한 패키지부터 `변수 초기화` → `init()` 순으로 실행된 뒤 `main()` 이 호출됨
+ 컴파일 에러가 되는 것
    - 사용하지 않는 import, 사용하지 않는 지역 변수
    - 여는 중괄호를 다음 줄에 쓰는 것
    - 한 폴더에 `func main()` 이 두 개 (`main redeclared in this block`)
+ 자주 쓰는 명령
    - `go run` 실행, `go build` 빌드, `go vet` 검사, `go fmt` 포맷
