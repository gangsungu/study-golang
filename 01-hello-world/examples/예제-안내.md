## 01. Go 시작하기 — 예제 안내

정리 문서: [Go 시작하기](../Go-시작하기.md)

### 실행 예제

**레포 루트에서** 실행합니다.

| 예제 | 확인하는 것 | 실행 |
|------|------------|------|
| [ex01-hello](ex01-hello/main.go) | 패키지 선언, `func main()`, `fmt.Println` | `go run ./01-hello-world/examples/ex01-hello` |
| [ex02-init-order](ex02-init-order/main.go) | `패키지 변수` → `init()` → `main()` 순서, blank import | `go run ./01-hello-world/examples/ex02-init-order` |
| [ex03-not-main-package](ex03-not-main-package/util.go) | `package main` 이 아니면 `func main()` 이 있어도 진입점이 아님 | `go run ./01-hello-world/examples/ex03-not-main-package` |

`ex02-init-order` 의 출력입니다. import한 `sub` 패키지가 먼저 끝나고, 그다음 `main` 패키지가 초기화된 뒤에야 `main()` 이 호출됩니다.

```
2. sub 패키지 변수 초기화
3. sub의 init()
4. main 패키지 변수 초기화
5. main.go의 init()
6. trace.go의 init()
7. main() - 여기서 비로소 진입점이 실행된다
```

> 같은 패키지 안 `init()` 의 순서는 **파일 이름 순**입니다(`main.go` < `trace.go`). 동작하긴 하지만 여기에 의존하는 코드를 쓰면 안 됩니다.

`ex03-not-main-package` 는 **빌드는 통과하지만 실행만 거부되는** 경우라서 `_errors/` 가 아니라 일반 예제로 두었습니다.

```bash
$ go build ./01-hello-world/examples/ex03-not-main-package
(통과)

$ go run ./01-hello-world/examples/ex03-not-main-package
package hello/01-hello-world/examples/ex03-not-main-package is not a main package
```

### 에러 예제

`_errors/` 안의 파일은 **일부러 컴파일에 실패하도록** 만든 예제입니다. 실행이 아니라 **에러 메시지를 읽는 것**이 목적입니다.

| 예제 | 확인하는 에러 |
|------|--------------|
| [err01-main-redeclared](_errors/err01-main-redeclared/) | `main redeclared in this block` — 한 폴더에 `main` 은 하나뿐 |

이 예제는 파일 두 개가 함께 컴파일되어야 에러가 나므로, 폴더 안의 `.go` 를 전부 지정해 실행합니다.

```bash
go run ./01-hello-world/examples/_errors/err01-main-redeclared/*.go
```

```
b.go:6:6: main redeclared in this block
	a.go:6:6: other declaration of main
```

> 파일을 나눠도 같은 폴더면 같은 패키지라 중복 선언입니다. 자바에서 클래스마다 `main` 을 둘 수 있는 것과 다른 지점입니다.

### 빌드해 보기

```bash
go build -o hello.exe ./01-hello-world/examples/ex01-hello
./hello.exe
```

`-o` 를 빼면 폴더 이름을 따라 `ex01-hello.exe` 가 만들어집니다.
빌드 산출물은 `.gitignore` 에서 제외되어 있습니다.
